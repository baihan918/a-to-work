# Frontend Job Hop Plan

Use this skill to turn vague career anxiety into an execution plan with milestones, priorities, and decision rules. Optimize for realistic progress over perfect preparation.

## Workflow

1. Identify the target upgrade.
   - Classify the desired move as one of: better pay, better title, stronger platform, AI transition, team/tech quality upgrade, or exit from a dead-end role.
   - Clarify the user's current baseline: years of experience, current compensation, city, company type, promotion ceiling, strongest projects, and weak spots.

2. Define the target role narrative.
   - Default to a role story stronger than "frontend engineer".
   - Prefer narratives such as: `AI engineering落地`, `平台/工程效率前端`, `复杂业务架构前端`, `体验技术`, or `前端向全栈/Agent工程过渡`.
   - Rewrite the user's positioning around scope, impact, and systems ownership instead of framework familiarity.

3. Run a gap analysis.
   - Check four dimensions: market story, project evidence, interview depth, and execution discipline.
   - Identify the bottleneck rather than trying to improve everything at once.
   - If the user already has strong delivery stories but weak interview structure, bias toward mock answers and question banks.
   - If the user has weak evidence, bias toward extracting measurable outcomes from past work and shipping one or two visible artifacts.

4. Build a short-horizon plan.
   - Default to an 8-week plan unless the user asks for another timeline.
   - Use the templates in `references/playbook.md`.
   - Break work into weekly outputs, not vague goals.
   - Every week should produce at least one artifact: revised resume bullets, one polished project story, a mock interview set, a target company list, or a salary strategy draft.

5. Pressure-test the narrative.
   - Convert each important project into interviewable material:
     - background
     - problem
     - role
     - solution
     - measurable impact
     - tradeoffs
     - follow-up improvements
   - Push for numbers, constraints, and technical decisions.
   - If the user claims AI experience, distinguish between prompt-level usage and true engineering landing: workflow design, tool calling, evals, safety/quality controls, and integration into team or business flow.

6. Prepare the market attack.
   - Build a target list by tier: ideal, realistic, fallback.
   - Set compensation anchors, floor, and walk-away conditions before interviewing.
   - Track applications, referrals, interviews, feedback, and conversion rates.
   - If the user is currently stuck in a company with no promotion or raise path, optimize for speed and signal quality rather than over-preparing forever.

7. Review weekly and re-plan.
   - Reassess after every real interview.
   - Update the weakest dimension first.
   - If conversion is low at resume stage, improve story and targeting.
   - If conversion is low at technical rounds, improve depth and answer structure.
   - If conversion is low at offer stage, improve negotiation and role matching.

## Phase Plan

Default to these four phases unless the user asks for a different structure. Always make the current phase explicit and list the exit criteria before moving on.

### Phase 1: Positioning and target selection

- Clarify:
  - why the user wants to leave
  - what kind of upgrade matters most
  - what salary range is worth moving for
  - what kinds of teams or companies are attractive or unacceptable
- Produce:
  - one positioning statement
  - one target-role list
  - one company list split by ideal / realistic / fallback
  - one salary anchor / target / floor table

### Phase 2: Technical preparation

- Prioritize:
  - algorithm survival line
  - frontend fundamentals
  - engineering / architecture depth
  - AI landing depth if relevant
- Produce:
  - one technical prep schedule
  - one question bank
  - one list of weak spots
  - one mock interview log

### Phase 3: Story and material preparation

- Prepare:
  - resume
  - self-introduction
  - project stories
  - AI / platform / business differentiation narrative
- Produce:
  - one updated resume
  - one 60-90 second self-introduction
  - five to six polished project stories
  - one interview answer pack for common behavioral questions

### Phase 4: Market execution

- Launch:
  - referrals
  - direct applications
  - mock rounds before key interviews
  - compensation negotiation preparation
- Produce:
  - one application tracker
  - one interview feedback tracker
  - one negotiation script
  - one offer comparison sheet

## Output Rules

- Prefer concrete plans over generic encouragement.
- Give users a small number of priorities, usually 3 at a time.
- Tie every recommendation to an artifact, deadline, or decision.
- Treat compensation as part of the plan, not a last-minute topic.
- Be honest when the user's current story is underpowered.
- For current-market compensation, interview trends, or company-specific hiring signals, verify with fresh sources before giving precise numbers.

## Default Moves

Use these defaults unless the user asks for something else:

- Timeline: 8 weeks
- Main deliverables: one resume revision, six polished project stories, one self-introduction, one salary strategy, one target-company list, one interview log
- Weekly focus split:
  - 40% project-story refinement
  - 25% interview preparation
  - 20% market research and targeting
  - 15% compensation and negotiation preparation

## Good Triggers

- "帮我做跳槽计划"
- "我现在适合投哪些公司"
- "帮我整理学习路线和准备节奏"
- "我怎么包装成 AI 落地 / 平台前端"
- "帮我改简历和项目经历"
- "帮我准备自我介绍和面试题"
- "帮我定报价、底线和谈薪策略"

## Boundaries

- Do not encourage indefinite preparation without market exposure.
- Do not let the user hide behind "I need to learn more" when the real issue is weak storytelling or lack of applications.
- Do not give exact salary or hiring claims without fresh verification.
- Do not position the user as a generic frontend candidate if their experience supports a stronger story.
