# React 原理

## 为什么 React 要分为协调阶段和提交阶段？

React 把一次更新拆成两个阶段：

- 协调阶段：也叫 render/reconciliation 阶段，负责在内存中计算新的 Fiber 树，比较新旧结构，标记需要新增、删除、更新的节点。
- 提交阶段：也叫 commit 阶段，负责把协调阶段算出的结果真正应用到宿主环境，比如修改 DOM、更新 ref、执行 `useLayoutEffect`，并安排 `useEffect`。

核心原因是：React 需要把“可中断的计算”和“不可中断的真实副作用”分开。

协调阶段主要是在内存中工作，还没有真正改 DOM。即使计算到一半被打断，也可以之后继续、重做，或者直接丢弃这次计算结果。因此 React 可以在这个阶段根据任务优先级进行调度，例如先响应用户输入、动画等更高优先级任务。

提交阶段则不同。它会真正改动页面和外部世界，一旦开始执行，就必须保证最终 UI、DOM、ref、生命周期和 effect 处于一致状态。

## 为什么提交阶段不能中断？

因为提交阶段执行的是可见副作用。如果中断，页面可能会暴露出一半新状态、一半旧状态。

例如一次更新同时影响两个组件：

```jsx
<Header user={user} />
<Profile user={user} />
```

如果 commit 阶段改完 `Header` 后被中断，而 `Profile` 还没有更新，用户可能看到 Header 已经是新用户，Profile 仍然是旧用户。这会造成 UI 不一致。

更严重的是，提交阶段还会处理 DOM、ref、`useLayoutEffect`、组件挂载和卸载等副作用。如果这些操作只执行一半，组件内部状态、真实 DOM 和外部可见结果之间就可能互相矛盾。

所以 React 的策略是：

1. 协调阶段可中断，因为它只是内存计算。
2. 提交阶段不可中断，因为它已经开始修改真实世界。

## 记忆方式

可以把协调阶段理解为“写草稿”：可以暂停、重写、丢弃。

可以把提交阶段理解为“发布上线”：一旦开始发布，就不能只发布一半。

因此，React 的并发能力主要发生在协调阶段，而不是提交阶段。
