# 05 JS / TS 基础

## JavaScript 高频题

### 1. 原型链怎么理解？

**答题口径**

每个对象都有内部原型，属性查找会先找自身，再沿原型链向上查找。函数有 `prototype`，通过 `new` 创建的实例会把内部原型指向构造函数的 `prototype`。

**注意点**

- `__proto__` 是对象的原型访问器。
- `prototype` 是函数用于构造实例原型的属性。

### 2. new 做了什么？

**答题口径**

`new` 会创建一个新对象，把新对象原型指向构造函数的 `prototype`，以新对象为 `this` 执行构造函数，如果构造函数返回对象则返回该对象，否则返回新对象。

### 3. this 指向怎么判断？

**答题口径**

`this` 取决于调用方式：

- 普通函数调用：非严格模式指向全局，严格模式是 `undefined`。
- 对象方法调用：指向调用对象。
- `call/apply/bind`：显式绑定。
- `new`：指向新实例。
- 箭头函数：没有自己的 `this`，继承词法作用域。

### 4. 闭包是什么？

**答题口径**

闭包是函数可以访问其创建时词法作用域中的变量，即使外层函数已经执行结束。它常用于封装私有状态、函数工厂、缓存、异步回调。

**注意点**

- 闭包不是一定导致内存泄漏。
- 长期持有大对象引用才可能造成泄漏。

### 5. Promise 怎么理解？

**答题口径**

Promise 是异步状态机，有 pending、fulfilled、rejected 三种状态。状态一旦改变不可逆。`then` 返回新 Promise，回调进入微任务队列。

**注意点**

- Promise 构造器里的代码同步执行。
- `then/catch/finally` 回调是微任务。
- async 函数返回 Promise。

### 6. async / await 本质是什么？

**答题口径**

`async/await` 是 Promise 的语法糖，让异步代码写起来像同步流程。`await` 会暂停当前 async 函数后续执行，把后续逻辑放到微任务中等待 Promise settle。

**注意点**

- `await` 不会阻塞整个主线程。
- 并行任务不要连续 await，要用 `Promise.all`。

### 7. JS 内存泄漏常见场景？

**答题口径**

常见包括未清理的定时器、事件监听、全局缓存、闭包长期持有大对象、DOM 引用未释放、订阅未取消、无限增长的 Map。

定位方式包括 Chrome Memory、heap snapshot、allocation timeline、监控内存曲线。

### 8. 防抖和节流区别？

**答题口径**

防抖是在连续触发结束后执行一次，适合搜索输入、窗口 resize 后计算。节流是在固定间隔内最多执行一次，适合滚动、拖拽、鼠标移动。

### 9. 异步并发控制怎么做？

**答题口径**

核心是维护执行中任务数和等待队列。每完成一个任务就从队列取下一个执行。业务上常用于批量请求、上传、图片处理。

**注意点**

- 要处理失败、顺序、取消和重试。
- 不要一次性 `Promise.all` 几百个请求。

### 10. 深拷贝怎么实现？

**答题口径**

简单数据可用 `structuredClone`。复杂兼容实现要处理对象、数组、Date、RegExp、Map、Set、循环引用、原型、函数等。业务里优先避免不必要的深拷贝，或使用成熟库。

**注意点**

- `JSON.parse(JSON.stringify())` 会丢失 `undefined`、函数、Symbol、Date 类型等。

## TypeScript 高频题

### 1. interface 和 type 区别？

**答题口径**

`interface` 更适合描述对象结构，支持声明合并和 extends。`type` 更灵活，可以表示联合类型、交叉类型、条件类型、元组等。

**注意点**

- 团队里保持一致比争论绝对优劣更重要。

### 2. 泛型解决什么问题？

**答题口径**

泛型让类型像参数一样传入，在保持类型安全的同时复用逻辑。常用于请求函数、组件 props、工具函数、表单 schema。

示例：

```ts
function request<T>(url: string): Promise<T> {
  return fetch(url).then(res => res.json());
}
```

### 3. 联合类型怎么做类型收窄？

**答题口径**

可以通过 `typeof`、`instanceof`、`in`、字面量判别字段、自定义类型守卫进行收窄。复杂业务建议使用 discriminated union。

### 4. never 有什么用？

**答题口径**

`never` 表示不可能出现的类型，常用于穷尽检查。

```ts
type Status = 'idle' | 'loading' | 'success' | 'error';

function assertNever(x: never): never {
  throw new Error(String(x));
}
```

### 5. Partial、Pick、Omit、Record 怎么用？

**答题口径**

这些是工具类型：

- `Partial<T>`：属性变可选。
- `Pick<T, K>`：选取部分属性。
- `Omit<T, K>`：排除部分属性。
- `Record<K, T>`：构造 key 到 value 的映射。

项目里常用于表单草稿、接口 DTO、配置表、策略表。

### 6. TS 如何提升大型项目可维护性？

**答题口径**

TS 的价值不是多写类型，而是把业务约束前置到编译期。比如接口响应类型、组件 props、权限枚举、状态机 action、表单 schema、策略映射都可以用类型约束，减少运行时错误和重构风险。

**注意点**

- 不要到处 `any`。
- 类型要表达业务语义，而不是机械补标注。
- 复杂类型要克制，可读性优先。

## 9 年前端加分题

### 如何设计一个类型安全的请求层？

请求函数用泛型描述响应类型，接口层定义 DTO，业务层做数据转换。错误结构统一，避免每个页面自己判断。对于枚举、状态和权限使用字面量联合类型约束。

### 如何设计组件 props 类型？

props 类型要区分必填和可选，事件回调用明确参数，互斥 props 可以用联合类型表达。复杂组件避免一个巨大的配置类型，必要时拆分为子配置。

### 如何避免 TypeScript 变成负担？

给公共边界加严格类型，内部简单逻辑保持清晰。避免过度类型体操。团队约定 `any`、类型断言、接口生成和迁移策略。
