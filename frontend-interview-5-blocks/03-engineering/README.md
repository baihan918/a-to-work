# 03 工程化

## 高频面试题

### 1. 从 0 搭一个中大型前端项目，你会怎么设计？

**答题口径**

先确定技术栈和边界，再设计目录、路由、权限、请求层、状态管理、组件体系、样式方案、质量规范、构建发布、监控告警。

一个可靠回答：

- 技术栈：React、TypeScript、Vite 或 Webpack。
- 目录：按业务模块和公共能力分层。
- 请求：统一封装鉴权、错误、重试、取消、埋点。
- 权限：路由权限、按钮权限、数据权限分层。
- 组件：基础组件复用设计系统，业务组件按场景沉淀。
- 质量：ESLint、Prettier、TypeScript、单测、E2E、CI。
- 发布：环境隔离、灰度、回滚、sourcemap 管理。
- 监控：错误、性能、接口、资源加载、用户行为链路。

**注意点**

- 9 年前端不能只说选 React。
- 要说团队协作和长期维护。

### 2. Webpack / Vite 构建流程怎么理解？

**答题口径**

Webpack 以入口为起点构建依赖图，经过 loader 转换不同资源，通过 plugin 介入构建生命周期，最后输出 bundle。Vite 开发阶段利用浏览器原生 ESM，按需转换模块，生产阶段通常用 Rollup 打包。

**注意点**

- Vite 快主要是开发阶段快，不是生产构建永远更快。
- loader 处理文件转换，plugin 处理构建流程扩展。

### 3. tree shaking 为什么可能不生效？

**答题口径**

tree shaking 依赖 ESM 的静态结构。失效原因包括使用 CommonJS、模块有副作用、Babel 转换破坏 ESM、包没有正确声明 `sideEffects`、动态访问导致无法静态分析。

**注意点**

- 要结合 bundle analyzer 看结果。
- 组件库要注意按需导出和样式副作用。

### 4. code splitting 怎么做？

**答题口径**

常见拆分包括路由级懒加载、重组件懒加载、第三方依赖拆分、业务模块拆分。目标是减少首屏必须加载的 JS，同时保持缓存稳定。

**注意点**

- 拆太碎会增加请求和调度成本。
- HTTP/2 下请求成本降低，但执行 JS 的成本仍然存在。
- 首屏关键路径优先级更重要。

### 5. sourcemap 线上怎么管理？

**答题口径**

线上可以生成 sourcemap 但不公开访问，上传到监控平台用于错误还原。产物和 sourcemap 版本要一一对应，发布后保留构建号，方便定位。

**注意点**

- 不要把完整 sourcemap 直接暴露公网。
- 回滚时也要对应正确版本。

### 6. 前端监控怎么设计？

**答题口径**

监控分错误、性能、请求、资源、用户行为和业务指标。错误包括 JS error、Promise rejection、React ErrorBoundary。性能包括 Web Vitals、长任务、资源加载。请求监控包括状态码、耗时、失败原因。行为链路用于复现问题。

**注意点**

- 监控不是只接 SDK。
- 要有采样、脱敏、聚合、告警、版本关联。

### 7. CI/CD 怎么设计？

**答题口径**

提交后跑 lint、typecheck、unit test、build。合并后生成版本产物，上传静态资源和 sourcemap，按环境发布。重要项目需要灰度、回滚和发布通知。

**注意点**

- 质量门禁要和团队成本平衡。
- 阻塞发布的检查要稳定，避免大家绕过。

### 8. 组件库怎么设计和发版？

**答题口径**

组件库要区分基础组件和业务组件。基础组件关注设计系统一致性、API 稳定、可访问性、主题能力。业务组件关注场景复用和效率。发版要遵循 semver、changelog、自动化测试、文档和迁移说明。

**注意点**

- 不要把所有业务差异都塞进一个大组件。
- API 设计要克制，避免布尔 props 爆炸。

### 9. Monorepo 适合什么场景？

**答题口径**

适合多包、多应用共享基础能力的团队，例如组件库、工具库、多个业务应用。好处是统一依赖、统一规范、方便联调和原子提交。成本是构建缓存、依赖边界、权限和发布流程复杂度上升。

**注意点**

- 不要为了时髦上 monorepo。
- 要有 pnpm workspace、changesets、构建缓存等配套。

### 10. 如何治理包体积？

**答题口径**

先用 bundle analyzer 定位大依赖。优化手段包括路由拆包、按需加载、移除重复依赖、替换重库、tree shaking、图片字体优化、现代浏览器产物、减少 polyfill。

**注意点**

- 包体积小不等于体验好，JS 执行成本也重要。
- 要关注首屏关键路径。

## 工程化项目表达模板

> 我做工程化的目标不是堆工具，而是降低团队交付成本和线上风险。比如我统一了请求错误处理、权限判断、埋点和监控接入，让新页面不用重复实现这些横切逻辑。上线后同类问题减少，排障时间从 X 降到 Y，新人接入成本也降低。
