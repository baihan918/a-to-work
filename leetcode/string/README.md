# String 题目索引

## 核心套路

字符串题常见思路：

- String Matching：查找一个字符串是否连续出现在另一个字符串里。
- Sliding Window：适合连续子串、固定长度窗口、最长/最短窗口问题。
- Hash Table / Frequency Count：适合判断字符种类和出现次数是否一致。
- Two Pointers：适合逐字符比较、窗口左右边界移动。

## 复习重点

### 子串 vs 子序列

字符串题先判断要求的是子串还是子序列。

- 子串：必须连续，例如 `fdi` 必须连续出现。
- 子序列：只要求相对顺序一致，中间可以夹其他字符。

`28. 找出字符串中第一个匹配项的下标` 是子串匹配。

### 顺序一致 vs 排列一致

再判断是否要求字符顺序完全一致。

- `28`：要求顺序完全一致，`needle = 'ab'` 只能匹配 `'ab'`。
- `567`：要求排列一致，`s1 = 'ab'` 可以匹配 `'ab'` 或 `'ba'`。

### Sliding Window

滑动窗口适合处理连续区间。

如果题目要求固定长度子串，比如 `567` 中窗口长度固定为 `s1.length`，可以维护两个频次数组：

- `need`：目标字符串的字符频次。
- `window`：当前窗口的字符频次。

窗口每次右移一位：

1. 加入右侧新字符。
2. 移除左侧旧字符。
3. 判断窗口是否满足条件。

### Frequency Count

当题目只关心字符种类和次数、不关心顺序时，优先考虑频次统计。

如果字符范围限定为小写字母，可以用长度为 `26` 的数组；如果字符范围不确定，可以用 `Map`。

### 边界条件

常见边界：

- `needle` 为空时，字符串匹配通常返回 `0`。
- 目标串长度大于原串时，直接返回失败。
- 循环起点不要越界，剩余长度不足时不需要继续匹配。
