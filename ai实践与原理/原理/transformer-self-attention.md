# Transformer 自注意力机制

## 先给结论

Transformer 是一种模型架构，自注意力机制是 Transformer 的核心能力之一。

它解决的问题是：

```text
一句话里的每个 token，应该重点参考哪些其他 token？
```

比如：

```text
我把苹果放进书包，因为它很重。
```

模型在理解“它”时，需要判断它更可能指向“苹果”还是“书包”。自注意力机制会让“它”和句子里的其他 token 建立关系，根据相关性重新生成“它”的上下文表示。

所以，自注意力的本质不是简单地“看全文”，而是：

```text
每个 token 根据当前上下文，动态分配对其他 token 的关注权重。
```

## Transformer 和 Re-rank 的关系

Transformer 不是 Re-rank 环节本身。

更准确地说：

```text
Transformer 是模型架构
Re-rank 是检索系统里的一个处理环节
```

在 RAG 或搜索系统中，常见流程是：

```text
用户问题
  -> 召回：BM25 / 向量检索 / 混合检索，先取 top 50 或 top 100
  -> Re-rank：用更精细的模型重新排序
  -> 选出 top 5 或 top 10
  -> 放入上下文，让大模型生成答案
```

Re-rank 环节经常会用 Transformer 模型，例如 BERT、RoBERTa、bge-reranker、cross-encoder。

原因是 Transformer 能同时看 query 和 document：

```text
query: Transformer 是 Re-rank 环节里的吗
document: Re-rank 可以使用 cross-encoder 对 query 和文档进行相关性评分
```

它可以判断两段文本是否真的相关。这比只看向量相似度更精细，但计算成本也更高，所以通常只对召回后的少量候选做重排。

## 自注意力在做什么

可以把自注意力理解成一句话内部的“相关性分配器”。

对于句子里的每个 token，它都会问：

```text
为了理解我自己，我应该参考哪些 token？
每个 token 应该参考多少？
```

例如：

```text
The animal didn't cross the street because it was too tired.
```

当模型处理 `it` 时，它可能会更关注：

```text
animal  权重高
street  权重低
tired   权重高
```

这样模型更容易判断 `it` 指的是 `animal`。

## Q、K、V 是什么

在自注意力里，每个 token 会被映射成三个向量：

```text
Query   Q：我想找什么信息
Key     K：我能被什么信息匹配
Value   V：我真正提供的内容
```

可以用更直观的方式理解：

```text
Q 像问题
K 像标签
V 像内容
```

每个 token 会拿自己的 Q 去和其他 token 的 K 做匹配，计算相关性。

相关性越高，说明当前 token 越应该关注对方。最后再按照这些权重，把其他 token 的 V 加权汇总，得到当前 token 的新表示。

## 计算过程

自注意力的经典公式是：

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d)) V
```

拆开看：

```text
QK^T
  -> 计算 token 之间的相关性分数

/ sqrt(d)
  -> 缩放分数，避免数值过大导致 softmax 过于极端

softmax
  -> 把分数变成权重，所有权重加起来等于 1

乘以 V
  -> 按权重汇总信息，得到新的 token 表示
```

简化成流程就是：

```text
当前 token 的 Q
  -> 和所有 token 的 K 算相关性
  -> 经过 softmax 得到注意力权重
  -> 用权重加权所有 token 的 V
  -> 得到当前 token 的上下文表示
```

## 为什么叫“自”注意力

因为 Q、K、V 都来自同一段输入序列。

也就是说，句子内部的 token 互相看、互相建模关系，所以叫 self-attention。

如果 Q 来自一个序列，K/V 来自另一个序列，那就更接近 cross-attention。例如解码器在生成答案时关注编码器输出，或者多模态模型中语言 token 关注图像特征。

## 它和普通词向量有什么区别

普通静态词向量里，“苹果”的向量基本固定。

但在 Transformer 里，“苹果”的表示会根据上下文变化：

```text
我吃了一个苹果。
我买了一台苹果电脑。
```

第一句里的“苹果”更接近水果，第二句里的“苹果”更接近品牌或设备。

自注意力机制让 token 的表示不再孤立，而是和上下文绑定。

## 多头注意力是什么

单个注意力头只能从一个角度计算 token 关系。

多头注意力就是并行做多组注意力计算，让模型从不同角度理解句子关系。

比如同一句话里，不同注意力头可能分别关注：

```text
语法关系
指代关系
位置关系
主题关系
实体关系
```

最后再把多个头的结果拼接、变换，形成更丰富的表示。

这也是为什么 Transformer 能同时捕捉多种语言关系，而不是只按线性顺序理解文本。

## 为什么它适合处理长距离依赖

传统 RNN 更偏按顺序读文本，距离越远的信息越容易衰减。

自注意力不需要一步步传递信息。理论上，一个 token 可以直接和序列中任意位置的 token 建立关系。

例如：

```text
小明把昨天刚买的、放在桌子上的、蓝色封面的书拿走了，因为他今晚要看它。
```

“它”和“书”之间隔了很多词，但自注意力可以直接计算它们的相关性。

这让 Transformer 更擅长处理长距离依赖、指代消解和上下文关系。

## 成本和局限

自注意力的代价是计算成本较高。

标准 self-attention 会计算序列中 token 两两之间的关系。如果序列长度是 n，那么注意力矩阵大致是：

```text
n * n
```

也就是复杂度接近：

```text
O(n^2)
```

所以输入越长，计算量和显存压力会快速上升。

这也是为什么大模型会有上下文窗口限制，也为什么长上下文模型需要做稀疏注意力、分块注意力、KV cache、检索增强等优化。

## 面试回答版本

可以这样说：

> Transformer 的自注意力机制，本质是让序列里的每个 token 根据上下文动态决定应该关注哪些其他 token。每个 token 会生成 Q、K、V 三个向量，用 Q 和其他 token 的 K 计算相关性，经过 softmax 得到注意力权重，再用这个权重对 V 做加权求和，得到新的上下文表示。这样同一个词在不同句子里可以有不同含义，也能建模长距离依赖。

如果面试官继续问 Q、K、V，可以补充：

> Q 可以理解成当前 token 想查询的信息，K 是其他 token 可供匹配的特征，V 是实际被聚合的内容。Q 和 K 决定“看谁”，V 决定“拿什么信息”。

如果问它和 Re-rank 的关系，可以补充：

> Transformer 是模型架构，Re-rank 是检索链路里的重排序环节。Re-rank 可以使用 Transformer cross-encoder，把 query 和候选文档一起输入模型，让模型基于二者的交互关系重新打分。但不能说 Transformer 就是 Re-rank。

## 一句话总结

```text
自注意力机制让每个 token 都能根据上下文，动态决定应该参考哪些 token，并把这些信息加权融合成新的语义表示。
```

它是 Transformer 能理解上下文关系、长距离依赖和语义变化的核心机制。
