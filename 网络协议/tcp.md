# TCP

## 为什么建立连接是三次握手，关闭连接是四次挥手？

核心原因：建立连接时，双方的“建立意愿”可以合并确认；关闭连接时，TCP 是全双工的，两个方向要分别关闭，不能强行合并。

## 三次握手

建立连接时：

```txt
客户端 -> 服务端：SYN，我想建立连接
服务端 -> 客户端：SYN + ACK，我同意，也想建立连接
客户端 -> 服务端：ACK，确认
```

第二次握手中，服务端可以把两件事合在一起发：

- `ACK`：确认收到了客户端的 `SYN`。
- `SYN`：告诉客户端，服务端也准备好了。

所以建立连接只需要三次。

如果只有两次握手，客户端无法确认服务端是否收到了自己的最终确认，也更容易受到历史旧连接报文的影响。第三次 `ACK` 可以让双方都确认彼此具备收发能力。

## 四次挥手

关闭连接时：

```txt
客户端 -> 服务端：FIN，我这边不发了
服务端 -> 客户端：ACK，知道了
服务端 -> 客户端：FIN，我这边也不发了
客户端 -> 服务端：ACK，知道了
```

为什么不能像握手一样，把 `ACK + FIN` 合并成一次？

因为 TCP 是全双工通信。客户端不发了，不代表服务端也马上不发了。

客户端发 `FIN` 的意思只是：

```txt
我这边的数据发完了，我要关闭“客户端 -> 服务端”这个方向。
```

但服务端可能还有数据没发完，所以服务端只能先回一个 `ACK`：

```txt
我知道你不发了，但我可能还有数据要继续发。
```

等服务端数据也发完了，再单独发 `FIN`：

```txt
我这边也发完了，可以关闭“服务端 -> 客户端”这个方向。
```

所以关闭连接通常需要四次。

## 记忆方式

三次握手：双方确认“能不能建立连接”。

四次挥手：两个方向分别确认“我不发了”。
