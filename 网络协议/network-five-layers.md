# 网络五层模型

网络五层模型从上到下是：

```txt
应用层
传输层
网络层
数据链路层
物理层
```

一句话总览：

应用层管“用什么服务”，传输层管“进程到进程”，网络层管“主机到主机”，数据链路层管“相邻设备”，物理层管“怎么把 0 和 1 发出去”。

## 应用层

应用层解决的是“用户和应用要使用什么网络服务”的问题。

它直接面向具体应用，为浏览器、邮箱、文件传输、域名解析等场景提供协议约定。

特点：

- 面向具体业务和应用场景。
- 规定应用之间如何组织和解释数据。
- 不负责数据怎么跨网络送达，底层传输由下面几层完成。

常见协议：

- `HTTP` / `HTTPS`：网页和接口请求。
- `DNS`：域名解析。
- `FTP`：文件传输。
- `SMTP`：邮件发送。

## 传输层

传输层解决的是“数据到达目标主机后，应该交给哪个进程”的问题。

网络层只能把数据送到某台机器，但一台机器上可能同时运行很多程序，例如浏览器、Web 服务、数据库服务。传输层通过端口号区分具体进程。

特点：

- 负责进程到进程之间的通信。
- 核心标识是端口号。
- 可以在网络层之上提供可靠传输，也可以只提供简单的数据发送能力。

常见协议：

- `TCP`：面向连接，可靠传输，提供重传、顺序控制、流量控制、拥塞控制。
- `UDP`：无连接，不保证可靠性，开销更小，常用于实时音视频、直播、游戏等场景。

和网络层的核心区别：

```txt
网络层：靠 IP 找机器。
传输层：靠端口找程序。
```

## 网络层

网络层解决的是“数据应该送到哪台主机，以及经过哪些路径送过去”的问题。

它负责主机到主机之间的寻址和路由选择。

特点：

- 负责跨网络传输。
- 核心标识是 IP 地址。
- 关注路径选择和数据包转发。
- 通常只提供尽力而为的传输，不保证一定送达，也不保证顺序。

常见协议：

- `IP`：负责寻址和路由。
- `ICMP`：用于网络诊断和错误通知，例如 `ping`。

常见设备：

- 路由器。

## 数据链路层

数据链路层解决的是“在同一个局域网或同一段链路里，数据怎么从一个相邻设备传到另一个相邻设备”的问题。

网络层负责跨网络找到目标方向，但真正一跳一跳地转发时，需要数据链路层在相邻节点之间传输数据帧。

特点：

- 负责相邻设备之间的数据传输。
- 核心标识是 MAC 地址。
- 以帧为单位传输数据。
- 可以进行差错检测，例如帧校验。

常见概念和设备：

- 以太网。
- MAC 地址。
- 交换机。

## 物理层

物理层解决的是“0 和 1 怎么在真实物理介质上传输”的问题。

它不关心数据代表什么，只负责把比特流变成电信号、光信号或无线电信号传出去。

特点：

- 负责比特流传输。
- 关注电压、频率、光信号、无线信号、接口标准等物理细节。
- 不理解 IP、端口、HTTP 这些上层语义。

常见介质：

- 网线。
- 光纤。
- 无线电信号。

## 总结

| 层级 | 解决什么问题 | 核心标识 | 常见协议/概念 |
| --- | --- | --- | --- |
| 应用层 | 用什么网络服务 | URL、域名、应用协议字段 | `HTTP`、`HTTPS`、`DNS` |
| 传输层 | 数据交给哪个进程 | 端口号 | `TCP`、`UDP` |
| 网络层 | 数据送到哪台主机 | IP 地址 | `IP`、`ICMP` |
| 数据链路层 | 相邻设备之间怎么传 | MAC 地址 | 以太网、交换机 |
| 物理层 | 0 和 1 怎么传出去 | 物理信号 | 网线、光纤、无线信号 |

## 记忆方式

从上到下记：

```txt
应用层：用户要用什么服务
传输层：端口找到具体程序
网络层：IP 找到目标机器
数据链路层：MAC 找到相邻设备
物理层：信号真正传输比特
```
